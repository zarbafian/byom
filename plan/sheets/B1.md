# Milestone sheet — B1: A society of two (attached slice)

- **Owner:** byom
- **Prerequisites:** B0.1 (implementation-ready via RT), C3a
  (implementation-ready via RT)
- **Operation/schema bundle:** the B0.1 bundle, implemented in `byomd`
  (personal profile: SQLite, per-surface Unix sockets, developer security
  profile honestly labeled)
- **Scope (the A7 attached slice — the hosted slice lands at I1 with
  K2/C3b; I0 confirms this slice only, never full byom §24 B1 exit):**
  - one human (direct governance channel, fresh phishing-resistant challenge)
    + one agent participant with a proposed-then-admitted `attached_harness`
    ManifestationRevision (`membership_offer` → candidate acceptance →
    `participant_admit` + `manifestation_admit`)
  - atomic `society_bootstrap` genesis; Charter r1; human sovereign seat;
    budget roots; event genesis
  - full onboarding state machine incl. refusal, revocation, expiry,
    candidate-channel fencing, and the §7.4 refusal-retry receipt
  - participant-owned self-policies (`ParticipantAssentPolicyRevision`,
    `ActivationPolicyRevision` adoption paths); provenance-labeled assent
    modes
  - the mandate chain (`mandate_prepare/position/issue` + budget reservation)
    before any non-pledged ActivityStream; exploration before any pledge;
    `wake_intent_submit` accepted and left pending (no activation machinery
    in this slice)
  - `endeavor_propose/position/finalize` → call → pledge with the full seat
    sequence → deterministic delivery → review; budgets reserved/settled;
    events cursored
- **Produced artifacts:** `byomd` + the `byom` CLI (personal profile), plus
  `byom-mcp`, the stdio MCP server exposing the C3a candidate and participant
  tool profiles over byomd's per-surface sockets; numbered SQLite migrations;
  authority journal with the developer-recovery witness profile (honestly
  advertised as "developer recovery" — the daemon prints
  `witness developer-recovery` at startup; B-ADR-3 backend not required yet)
- **Migrations:** B1 domain tables as numbered migrations
- **Assurance profile:** developer (labeled); no confinement claims
- **Verification (commands + test IDs):**
  - `cargo test -p byomd --test b1_acceptance` — agent notices/explores first
    (under its mandate), then accepts one Pledge, survives daemon
    kill/restart at every commit point, delivers a reviewable change-set with
    a complete causal timeline
  - `cargo test -p byomd --test b1_onboarding_negative` — the C3a negative
    suite server-side, plus: terminal offers never admit; stale acceptance
    expires; accepted→refused retraction; refusal/admission same-revision
    race; post-admission credential fencing; **a pre-admission candidate
    self-policy activates at `participant_admit` exactly as authored, never
    before Standing**; **neither governance nor any runtime identity can
    install or broaden participant/candidate self-policy**
    (`assent_policy_adopt`/`activation_policy_adopt` on the governance or
    runtime surface → `forbidden_surface`; snake_case is byom's spelling —
    the kebab-case `forbidden-surface` this sheet originally wrote is kovee's
    convention and never satisfies a byom problem field, PROFILE.md §3.1)
  - `cargo test -p byomd --test b1_mandate_negative` — exploration refused
    without a mandate, and with a held, revoked, expired, exhausted, or
    insufficient one
  - `cargo test -p byomd --test b1_cease` — `participation_cease` mid-work:
    self-only, unconditional, immediate fencing; wrong-actor and
    conditional-exit attempts fail; replay idempotent; obligations
    dispositioned independently
  - `cargo test -p byomd --test b1_journal` — fault injection at every
    authority-journal boundary: SQL-prepare-before-CAS, lost witness
    reply/lookup, CAS-before-finalize, competing CAS, rollback, startup
    comparison → `sealed_diagnostic` closes every non-diagnostic surface; no
    early result/event/permit; continuous generations; exact recovery or
    abandonment
  - `cargo test -p byomd --test b1_privacy_access` — chained
    `PrivacyAccessRecord` for allowed and denied sensitive reads: canonical
    query/scope digest, result cardinality **and byte counts**, dependency
    binding, **and failure behavior (a failed record write blocks the
    read)**; operator-resistant witnessing explicitly unclaimed
  - `cargo test -p byomd --test b1_classification` — attached-harness output
    gets Society top label or quarantine absent complete-readable-source
    attestation
  - `python3 conformance/run.py --live` — replays the slice-op request
    vectors against a spawned `byomd`. **Correction to the original sheet:**
    it named `python3 conformance/run.py bundles/b0.1 --live` (the runner
    takes no bundle argument — the bundle is registry-derived) and
    `npm test --prefix conformance-ts -- --live`. There is no
    `conformance-ts` client, so the live replay is single-client; the
    "two independent clients" property this sheet claimed is **not met**.
    What is doubled elsewhere is the BPA-1 evaluator and the family-vector
    rederiver (B0.1 sheet).
  - `./run-checks.sh` runs all of the above plus the I0 and I1 gates.
    It exits **2** by design without `I1_REAL_HARNESS=1`: the two
    real-harness cells report SKIP, and the I1 gate refuses to score a skip
    as a pass.
